# Live demo: 2-minute recording guide

A real camera demonstration is required by the challenge. A preview-only screen recording does not meet the rules. Record only yourself, with your informed consent, in a private space. Do not include your developer dashboard, key, terminal secrets or bystanders.

## Record on Windows
1. Run `npm ci`, then `npm start` from the project folder.
2. Complete the live consent/key flow **before** starting the public recording; the key is masked, but avoid filming the key step at all.
3. Wait for valid live measurements and baseline. A front camera with upper torso visible and even lighting works best.
4. Use Windows Snipping Tool screen recording or OBS from its official source. Frame the Stillwater window so the LIVE PRESAGE label and breathing trace are visible. A face preview is optional to the story; publish your own face only if comfortable.
5. Record this sequence:
   - 0:00–0:15: “I'm Aditya. Stillwater makes a reading interface respond to the person reading, using live Presage breathing signals.”
   - 0:15–0:40: Show live breaths/min, real trace, readiness and calibrated baseline. “These values come from SmartSpectra, not a timer or an LLM.”
   - 0:40–1:10: Start reading. “Relative breathing changes gently alter paragraph dwell time. The lake reflects chest movement and uses breathing rate to time its ripples. It is an artistic response, not a medical interpretation.”
   - 1:10–1:30: Move out of frame briefly and show the readiness warning. “When signal quality drops, adaptation stops. Missing data never becomes a made-up reading.”
   - 1:30–1:45: Return, show custom text/manual reading/reduced motion.
   - 1:45–2:00: Stop. Show camera preview disappearing and metric clearing. “No app recording, no saved metrics, SDK aggregate telemetry disabled. You can always read manually.”
6. Review the recording for real metrics, visible live mode, secrets and personal background details.
7. Upload it as a public or unlisted YouTube video. Add its final URL to the DEV draft. A working public video is required; local file paths are insufficient.
